This lab continues from stages 1 and 2 of the Linux Lab. The scenario is that Oracle Database 19c (installed version 19.3) has been installed on dbserver02, prepared in stage 2, and the ORCL database has been created. Commands and procedures are based on the official Oracle Database 19c documentation (Administrator's Guide, SQL Language Reference, SQL*Plus User's Guide, Net Services Reference, Backup and Recovery User's Guide, Database Reference, Error Messages, Database Patch Maintenance, SQL Tuning Guide, PL/SQL Packages and Types Reference), and each lesson lists its source documents.

Output confirmed against examples in the official documentation: the format of the SQL*Plus startup banner (the documentation example is 19.1); for STARTUP, "Connected to an idle instance.", "ORACLE instance started.", the SGA line names, "Database mounted.", "Database opened.", and for SHUTDOWN, "Database closed.", "Database dismounted.", "ORACLE instance shut down." (Oracle 19c startup and shutdown tutorial); the formats of lsnrctl status, start, stop, and services; the output format of tnsping; the format of the rman startup banner and connection messages; the old/new RMAN configuration parameters messages of CONFIGURE; the heading lines of LIST BACKUP SUMMARY; CROSSCHECK result lines and "Crosschecked n objects"; "deleted backup piece" and "Deleted n objects" for DELETE; the format of ARCHIVE LOG LIST (archivelog mode); the KILLED and PSEUDO markers after KILL; the ORA-, RMAN-, and TNS- error messages quoted in the lessons (including ORA-19573, ORA-01124, ORA-38312, ORA-01541, RMAN-06094, RMAN-06149, TNS-12560, TNS-00511); the SP2-0771, SP2-0606, SP2-0223, and SP2-0103 messages; and the column headings of SHOW PARAMETER (NAME, TYPE, VALUE). In stage 5: the RMAN-06056 line of VALIDATE DATABASE; the RESTORE and RECOVER progress lines that appear in documentation examples (Starting restore/recover at, restoring datafile, restore complete, starting media recovery, archived log ... is on disk as file, media recovery complete, Finished); the column headings and DROP TIME format of SHOW RECYCLEBIN; and the column names of V$RECOVER_FILE, V$RECOVERY_FILE_DEST, and DBA_RECYCLEBIN. In stages 6 and 7: the SET UNTIL, RESTORE, RECOVER order in an RMAN RUN block; the RESTORE CONTROLFILE FROM AUTOBACKUP procedure; the ORA-01589, ORA-01139, ORA-01152, and ORA-01861 messages; the questions of awrrpt.sql (report_type, num_days, begin_snap, end_snap, report_name) and the default report name; and the names of wait events and wait classes. In stage 10: the shape of SHOW CONFIGURATION and of SHOW DATABASE for the standby; the Database Role, Ready for Switchover, and Ready for Failover lines of VALIDATE DATABASE; "Succeeded." after EDIT DATABASE ... SET STATE; the SWITCHOVER progress lines and "Switchover succeeded, new primary is ..."; DGMGRL's "Welcome to DGMGRL..." and "Connected as SYSDG." lines (Data Guard Broker 19c examples); and the columns and NAME values of V$DATAGUARD_STATS and the fact that it has no rows on the primary (Database Reference 19c). Output not confirmed: feedback messages such as "User created." after DDL; the column widths of SHOW PARAMETER; the line format of SHOW ALL; SPOOL status messages; ARCHIVE LOG LIST in NOARCHIVELOG mode; the 19.0.0.0.0 version notation in the RMAN startup banner; the RMAN BACKUP progress lines and the REPORT NEED BACKUP table; the table of files to delete in DELETE OBSOLETE; the full order of lsnrctl error lines when there is no listener; orapwd's password prompts and OPW-00005; some error messages not quoted in the lessons; the output of SQL statements run at the RMAN prompt in stage 5; the remaining RESTORE progress lines; "Flashback complete."; the column widths and BIN$ name shape of SHOW RECYCLEBIN; "executing command: SET until clause" and the RESTORE CONTROLFILE progress lines in stage 6; online redo log apply lines; "PL/SQL procedure successfully completed." in stage 7; the guidance text and snapshot list layout of awrrpt.sql; the layout and numbers of the AWR report body; the Rows, Bytes, Cost, Time numbers and Plan hash value of the stage 9 execution plans (the plan layout and column headings, Predicate Information, and "Explained." were confirmed with SQL Tuning Guide 19c and DBMS_XPLAN examples); the DISPLAY_CURSOR privilege error message; the full OPatch and datapatch screens in stage 8 (the documentation has no output examples; only the "Log file for this invocation:" line was confirmed in the 26ai documentation) and the unzip output. The patch numbers, RU versions, and OPatch version numbers in stage 8 are example values. In stage 10, the edition and copyright lines among DGMGRL's startup lines, the SHOW DATABASE output for the primary, how lag is shown when it is in hours (e.g. 2 hours 14 minutes 9 seconds), the Configuration Status and VALIDATE verdict while apply is stopped, the UNIT values of V$DATAGUARD_STATS, the process names, PIDs, and line layout of V$DATAGUARD_PROCESS, and the server names and IPs were also not confirmed or are example values. This output tries to follow the format seen in real 19c, but it could not be confirmed in the official documentation, and the screen says so with an ⓘ line.

Stage 4 SQL basics: confirmed in the official documentation are the format of the ORA-00001 and ORA-01400 error messages (Database Concepts 19c examples), "Table created." and the "n rows selected." behavior of SET FEEDBACK, EXITCOMMIT defaulting to ON (commit) when SQL*Plus exits, that a zero-length string is NULL and that = NULL is not true, that aggregate functions other than COUNT(*) ignore NULLs, that a left outer join fills unmatched rows with NULLs, and that DDL implicitly commits before and after (SQL Language Reference 19c). Not confirmed: DML feedback messages such as "1 row created./updated./deleted.", the full screen text of ORA-02291, 02292, 01407, 12899, 01722, 01438, 00937, 00979, and 01427, how the position of NULLs in sorting is displayed, and column widths. Such lines get an ⓘ mark in the terminal. The employee and department rows of the STUDY schema and the constraint names (SYS_C...) are illustrative examples.

Stage 11 RAC basics: confirmed in the official documentation are the per-node CRS-4537, 4529, and 4533 line format of crsctl check cluster -all (Clusterware 19c documentation example); the -n, -s, -c, -l, and -t options of olsnodes and the -n output example; the structure of the crsctl stat res -t table and the "Instance ... is running on node ..." message (21c Private Cloud Appliance documentation example); that CRSCTL is in the Grid home's bin and SRVCTL is run from the database home; that SRVCTL prints nothing on success; the -stopoption values of stop instance; the -oldinst and -newinst syntax of relocate service; the meaning of preferred and available instances and that a service does not automatically return to its original instance; INST_ID in GV$ views; and the gc cr block 2-way and gc current block 2-way wait events and the Cluster wait class (Real Application Clusters Administration and Deployment Guide 19c, Database Reference 19c). Not confirmed: the exact wording of the lines of srvctl status and config service and config database, the "is not running" message, the column spacing of crsctl stat res -t and the service resource names (ora.paydb.*.svc), the screen text of check crs and query crs activeversion, the capitalization of olsnodes -s, and the PRC and PRK error numbers on failure (replaced with ⓘ guidance instead of being made up). Cluster, node, DB, and service names, IPs, session counts, and times are illustrative examples. Lessons 104 to 108 (reflecting the RAC 19c CRSCTL and SRVCTL field guide): confirmed in the official documentation are the operators of the crsctl stat res -w filter (=, !=, co, st, en, AND, OR) and the advice not to manage ora. resources directly with CRSCTL, that cluster commands depend on OHASD (Clusterware 19c), the column layout of crsctl query css votedisk (19c OCR and voting files chapter example), the CRS-4639 message (19c error messages), the meaning of query crs activeversion -f (CRS-04172 usage), the line names and order and the -all option of srvctl config database, -startoption defaulting to OPEN, that disable database also disables the instances, not running SRVCTL on the same target concurrently, exit codes 0, 1, and 2, -eval, and the meaning of the -statefile and -scannumber options (RAC 19c), usage examples of -drain_timeout, -stopoption, and -failover for stop instance and relocate service (High Availability Overview 19c), and the layout of srvctl config asm and status asm -verbose (Clusterware 19c). Confirmed only in the 11.2 CRSCTL documentation because part of the 19c documentation could not be read: the CRS-4638 line of check crs, CRS-4622 and CRS-4621 of config crs, the explanation that stop crs fails if resources remain and -f stops unconditionally, the explanation that for several nodes stop cluster prevents resource relocation, the "Located n voting disk(s)." line, and the NAME=, TYPE=, TARGET=, STATE= layout without -t. Not confirmed: the progress lines of crsctl stop crs and start crs (CRS-2791, 2673, 2677, 2793, 4133, 4123, 2672, 2676, 6016, 6017, 6023, 6024), the full list and detailed wording of the -init table, the official definitions of Target and State values (INTERMEDIATE, UNKNOWN, etc.), the "Instance status:" wording of srvctl status -detail, the line wording of config scan, scan_listener, vip, network, nodeapps, listener, and service, the wording of status diskgroup and vip, the full syntax of stop home and start home and the contents of the state file, the description of the -wait option, and the error numbers when privileges are missing. Of the explanations in the field guide the site owner provided, "crsctl stop crs with the DB open may use shutdown abort" and "stop diskgroup -force does not stop the DB first" could not be confirmed in the official documentation, and the lessons say so.

The SQL engine imitates only what the lab needs: SELECT (joins, outer joins, subqueries, WHERE, GROUP BY, HAVING, ORDER BY, aggregate functions), INSERT, UPDATE, DELETE, COMMIT, and ROLLBACK on the lab's STUDY schema, and a few DDL statements. Numbers, dates, SIDs, PIDs, DBIDs, backup file names, and rows of business tables are illustrative examples.
