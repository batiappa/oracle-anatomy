      About this project
      
      
      A learning site for new DBAs who run Oracle 19c on Linux: first see the principles as pictures, then do the same things yourself with commands in the DBA labs. Each scene has a "Practice this" link that takes you straight to the matching lab lesson.
      
      
      Created by: Mr.Oracle (Kim Youngjo) · ambrokim@gmail.com · GitHub repository
      
    
      
    
      
      
      Notes
      
      
      The explanations follow the official Oracle Database 19c documentation. The server name (dbserver02), SGA_TARGET of 8G, the 4096 HugePages and the sysctl file name, and the sizes on the STARTUP screen match the virtual servers in the Linux and DBA labs; the change to 12G, PIDs and times are example values. That background processes on Linux are named ora_name_SID was not confirmed directly in the pages read; it matches the lab screens. The alert log wording and error number when HugePages run short are not given in the documentation, so they are shortened with an ellipsis (…). The shared pool subcomponents and part of the PGA_AGGREGATE_LIMIT description come from a summary of the later part of the pages, and the formula for the PGA_AGGREGATE_LIMIT default was not confirmed, so it is not given. Of the USE_LARGE_PAGES values, only ONLY and AUTO_ONLY were confirmed in the pages read.
      
      
      Sources: Oracle Database 19c Concepts · Memory Architecture (SGA and PGA contents, memory management methods, STARTUP output), Concepts 19c · Process Architecture (server processes, mandatory background processes), Administrator's Guide 19c · Managing Memory (AMM, ASMM, PGA_AGGREGATE_TARGET and LIMIT, V$SGAINFO), Administrator's Reference 19c · Administering Oracle Database on Linux (HugePages, relation to AMM, Transparent HugePages, computing the number of pages), High Availability Overview and Best Practices · Database Configuration Best Practices (USE_LARGE_PAGES=ONLY).
