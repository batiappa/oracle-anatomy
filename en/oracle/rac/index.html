      About this project
      
      
      A learning site for new DBAs who run Oracle 19c on Linux: first see the principles as pictures, then do the same things yourself with commands in the DBA labs. Each scene has a "Practice this" link that takes you straight to the matching lab lesson.
      
      
      Created by: Mr.Oracle (Kim Youngjo) · ambrokim@gmail.com · GitHub repository
      
    
      
    
      
      
      Notes
      
      
      The explanations follow the official Oracle Database 19c documentation. The server names (racnode1, racnode2), database (PAYDB), instances (PAYDB1, PAYDB2), services (pay_oltp, pay_batch) with their preferred and available settings, and the 03:10 reboot and 07:40 return match DBA labs stage 11; session counts and wait counts are example values. Part of the description of the -failback option (19.3 and later) and of services moving to an available instance comes from a summary of the RAC Administration Guide. That a surviving instance performs the recovery was confirmed in Concepts, but how it reads the failed instance's redo and how recovery proceeds phase by phase were not confirmed in the original text and are not covered. The crsctl and srvctl output is trimmed, and the state shown in the crsctl resource table after a VIP fails over and the gc statistic names in GV$SYSSTAT were not confirmed in the pages read, so they may differ from real output.
      
      
      Sources: Real Application Clusters Administration and Deployment Guide 19c · Introduction to Oracle RAC (instances, redo threads, undo, Cache Fusion, GCS, GES, GRD, interconnect, VIP, SCAN), RAC 19c · Glossary (LMON, LMS, Cache Fusion, GCS), RAC 19c · Workload Management with Dynamic Database Services (preferred and available, no automatic failback, -failback), Database Reference 19c · Descriptions of Wait Events (gc cr request, gc current request, gc buffer busy acquire, gc cr block 2-way and 3-way), Concepts 19c · Oracle Database Instance (redo threads, instance recovery by a surviving instance).
