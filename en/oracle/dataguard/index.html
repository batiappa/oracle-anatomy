      About this project
      
      
      A learning site for new DBAs who run Oracle 19c on Linux: first see the principles as pictures, then do the same things yourself with commands in the DBA labs. Each scene has a "Practice this" link that takes you straight to the matching lab lesson.
      
      
      Created by: Mr.Oracle (Kim Youngjo) · ambrokim@gmail.com · GitHub repository
      
    
      
    
      
      
      Notes
      
      
      The explanations follow the official Oracle Database 19c documentation. The server names (dbserver02, dbserver03), database names (orcl, orclstby), configuration name (orcl_dg) and maximum performance mode match DBA labs stage 10; the failure scenario, times, lag values and log numbers are example values. The FAILOVER and REINSTATE DATABASE output, and ORA-16661 shown for the old primary after failover, follow the output in the examples chapter of Data Guard Broker 19c (Scenarios 10 and 11). The SHOW CONFIGURATION, VALIDATE DATABASE and V$DATAGUARD_PROCESS screens are trimmed, and the V$STANDBY_LOG status values may differ from real output. The detailed apply processes on the standby (such as PRnn) and the names of ASYNC transport processes are not covered.
      
      
      Sources: Data Guard Concepts and Administration 19c · Introduction (physical standby, protection modes, switchover and failover), Redo Transport Services (SYNC, ASYNC, standby redo logs, RFS), Redo Apply Services (MRP, real-time apply), Data Guard Protection Modes, Role Transitions (data loss in failover, reinstating the old primary), Data Guard Broker 19c · Switchover and Failover Operations (FAILOVER, IMMEDIATE, REINSTATE DATABASE, ORA-16661, fast-start failover), Data Guard Broker 19c · Managing Configuration Members (APPLY-ON/OFF, TRANSPORT-ON/OFF), Data Guard Broker 19c · Examples Using DGMGRL (Scenario 10 manual failover, Scenario 11 reinstatement output).
