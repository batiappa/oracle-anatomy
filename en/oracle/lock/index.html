      About this project
      
      
      A learning site for new DBAs who run Oracle 19c on Linux: first see the principles as pictures, then do the same things yourself with commands in the DBA labs. Each scene has a "Practice this" link that takes you straight to the matching lab lesson.
      
      
      Created by: Mr.Oracle (Kim Youngjo) · ambrokim@gmail.com · GitHub repository
      
    
      
    
      
      
      Notes
      
      
      The explanations follow the official Oracle Database 19c documentation. The server name (dbserver02), accounts (APP, APP_BATCH) and session number 142 match the DBA labs stage 3 lesson "Clear the session that holds a lock"; table names, row values, times and second counts are example values. The column layout of the V$SESSION query results could not be confirmed against documentation examples. The statements that row-lock information lives only in the block and is never escalated, and that a deadlock rolls back only one statement, come from a summary of the later part of the Concepts chapter. The error number for DDL blocked by DML locks and the wait class of enq: TX - row lock contention were not found in the pages read, so they are not given.
      
      
      Sources: Oracle Database 19c Concepts · Data Concurrency and Consistency (row locks TX, table locks TM, ITL, readers and writers, deadlocks, lock duration), Database Reference 19c · Descriptions of Wait Events (enq: TX - row lock contention), Database Reference 19c · Oracle Enqueue Names (TX, TM), Database Performance Tuning Guide 19c · Instance Tuning Using Performance Views (blocking session in V$SESSION, V$LOCK).
