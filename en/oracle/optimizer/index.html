      About this project
      
      
      A learning site for new DBAs who run Oracle 19c on Linux: first see the principles as pictures, then do the same things yourself with commands in the DBA labs. Each scene has a "Practice this" link that takes you straight to the matching lab lesson.
      
      
      Created by: Mr.Oracle (Kim Youngjo) · ambrokim@gmail.com · GitHub repository
      
    
      
    
      
      
      Notes
      
      
      The explanations follow the official Oracle Database 19c documentation. The server name (dbserver02) and the app account (APP) match the DBA labs; the DELIVERY_LOG table, the IX_DLOG_CUST index, the migration scenario and numbers such as row counts, block counts, costs and times are example values. The execution plan screens follow the column headings in the documentation (Id, Operation, Name, Rows, Bytes, Cost (%CPU), Time), but the Bytes and Time columns are dropped to fit the screen. The reason the optimizer chose a full scan in this example is explained with the "small table" entry in the SQL Tuning Guide's table of reasons for full scans; the actual cost formula is not published in the documentation. When a cursor already in the shared pool is hard parsed again after new statistics are gathered (the invalidation timing) was not confirmed, so it is described only as "at the next hard parse". Part of the description of the default dynamic statistics level and automatic statistics collection comes from a summary of the documentation.
      
      
      Sources: SQL Tuning Guide 19c · Query Optimizer Concepts (transformer, estimator, plan generator; selectivity, cardinality, cost; adaptive plans), SQL Tuning Guide 19c · Optimizer Statistics Concepts (kinds of statistics, dynamic statistics, automatic statistics collection), SQL Tuning Guide 19c · Optimizer Access Paths (reasons for full scans, index range scans), SQL Tuning Guide 19c · Generating and Displaying Execution Plans (DISPLAY_CURSOR, difference from EXPLAIN PLAN), SQL Tuning Guide 19c · SQL Processing (hard parse and optimization).
