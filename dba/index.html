만든 사람: 미스터오라클(김영조) · ambrokim@gmail.com · GitHub 저장소

이 실습은 1·2단계 리눅스 실습실에서 이어집니다. 2단계에서 준비한 dbserver02에 Oracle Database 19c(설치 버전 19.3)를 설치하고 ORCL 데이터베이스를 만든 상황입니다. 명령과 절차는 Oracle Database 19c 공식 문서(Administrator's Guide, SQL Language Reference, SQL*Plus User's Guide, Net Services Reference, Backup and Recovery User's Guide, Database Reference, Error Messages, Database Patch Maintenance, SQL Tuning Guide, PL/SQL Packages and Types Reference)를 기준으로 삼았고, 레슨마다 근거 문서를 붙였습니다.

공식 문서 예시로 확인한 출력: SQL*Plus 시작 화면의 형식(문서 예시는 19.1), STARTUP의 "Connected to an idle instance.", "ORACLE instance started.", SGA 줄 이름, "Database mounted.", "Database opened."와 SHUTDOWN의 "Database closed.", "Database dismounted.", "ORACLE instance shut down."(Oracle 19c 시작·종료 튜토리얼), lsnrctl status·start·stop·services의 형식, tnsping의 출력 형식, rman 시작 문구의 형식과 접속 문구, CONFIGURE의 old/new RMAN configuration parameters 문구, LIST BACKUP SUMMARY의 제목 줄, CROSSCHECK 결과 줄과 "Crosschecked n objects", DELETE의 "deleted backup piece"와 "Deleted n objects", ARCHIVE LOG LIST(아카이브 모드)의 형식, KILL 뒤의 KILLED·PSEUDO 표시, 레슨에 인용한 ORA-·RMAN-·TNS- 오류 문구(ORA-19573·ORA-01124·ORA-38312·ORA-01541·RMAN-06094·RMAN-06149·TNS-12560·TNS-00511 포함), SP2-0771·SP2-0606·SP2-0223·SP2-0103 문구, SHOW PARAMETER의 열 제목(NAME, TYPE, VALUE). 5단계에서는 VALIDATE DATABASE의 RMAN-06056 줄, RESTORE·RECOVER 진행 줄 중 문서 예시에 있는 줄(Starting restore/recover at, restoring datafile, restore complete, starting media recovery, archived log ... is on disk as file, media recovery complete, Finished), SHOW RECYCLEBIN의 열 제목과 DROP TIME 형식, V$RECOVER_FILE, V$RECOVERY_FILE_DEST, DBA_RECYCLEBIN의 열 이름. 6·7단계에서는 RMAN RUN 블록의 SET UNTIL·RESTORE·RECOVER 순서, RESTORE CONTROLFILE FROM AUTOBACKUP 절차, ORA-01589·ORA-01139·ORA-01152·ORA-01861 문구, awrrpt.sql의 질문(report_type, num_days, begin_snap, end_snap, report_name)과 기본 보고서 이름, 대기 이벤트와 대기 클래스 이름. 10단계의 SHOW CONFIGURATION과 대기 DB의 SHOW DATABASE 모양, VALIDATE DATABASE의 Database Role·Ready for Switchover·Ready for Failover 줄, EDIT DATABASE ... SET STATE 뒤의 "Succeeded.", SWITCHOVER의 진행 줄과 "Switchover succeeded, new primary is ...", DGMGRL의 "Welcome to DGMGRL..."과 "Connected as SYSDG." 줄(Data Guard Broker 19c 예시), V$DATAGUARD_STATS의 열과 NAME 값, 주 DB에서 행이 없다는 점(Database Reference 19c). 확인하지 못한 출력: DDL 뒤의 "User created." 같은 피드백 문구, SHOW PARAMETER의 열 폭, SHOW ALL의 줄 형식, SPOOL 상태 문구, NOARCHIVELOG일 때의 ARCHIVE LOG LIST, RMAN 시작 문구의 19.0.0.0.0 버전 표기, RMAN BACKUP 진행 줄과 REPORT NEED BACKUP의 표, DELETE OBSOLETE의 지울 목록 표, 리스너가 없을 때 lsnrctl의 오류 줄 전체 순서, orapwd의 암호 질문 문구와 OPW-00005, 레슨에 인용하지 않은 일부 오류 문구, 5단계의 RMAN 프롬프트에서 SQL 문을 실행할 때의 출력, 나머지 RESTORE 진행 줄, "Flashback complete.", SHOW RECYCLEBIN의 열 폭과 BIN$ 이름 모양, 6단계의 "executing command: SET until clause"와 RESTORE CONTROLFILE 진행 줄, 온라인 리두 로그 적용 줄, 7단계의 "PL/SQL procedure successfully completed.", awrrpt.sql의 안내문과 스냅샷 목록 모양, AWR 보고서 본문의 모양과 숫자., 9단계 실행 계획의 Rows·Bytes·Cost·Time 숫자와 Plan hash value(계획의 모양과 열 제목, Predicate Information, "Explained."는 SQL Tuning Guide 19c와 DBMS_XPLAN 예시로 확인), DISPLAY_CURSOR 권한 오류 문구, 8단계의 OPatch와 datapatch 화면 전체(문서에 출력 예시가 없음, "Log file for this invocation:" 줄만 26ai 문서에서 확인)와 unzip 출력. 8단계의 패치 번호, RU 버전, OPatch 버전 번호는 설명용 예시 값입니다. 10단계의 DGMGRL 시작 줄 가운데 판 번호·저작권 줄, 주 DB 쪽 SHOW DATABASE 출력, 지연이 시간 단위일 때의 표시(예: 2 hours 14 minutes 9 seconds), 적용을 멈춘 상태의 Configuration Status와 VALIDATE 판정, V$DATAGUARD_STATS의 UNIT 값, V$DATAGUARD_PROCESS의 프로세스 이름·PID·줄 구성, 서버 이름과 IP도 확인하지 못했거나 예시 값입니다. 이런 출력은 실제 19c에서 보이는 형식을 따르려 했지만 공식 문서로는 확인하지 못했고, 화면에 ⓘ 줄로 함께 알려 줍니다.

4단계 SQL 기초: 공식 문서로 확인한 것은 ORA-00001·ORA-01400 오류 문구의 형식(Database Concepts 19c 예시), "Table created."와 SET FEEDBACK의 "n rows selected." 동작, SQL*Plus 종료 때 EXITCOMMIT 기본값 ON(커밋), 길이 0인 문자열이 NULL이라는 점과 = NULL이 참이 아니라는 점, COUNT(*)를 뺀 집계 함수가 NULL을 무시한다는 점, 왼쪽 외부 조인이 짝 없는 행을 NULL로 채운다는 점, DDL이 앞뒤로 암묵 커밋한다는 점(SQL Language Reference 19c)입니다. 확인하지 못한 것: "1 row created./updated./deleted." 같은 DML 피드백 문구, ORA-02291, 02292, 01407, 12899, 01722, 01438, 00937, 00979, 01427의 화면 문구 전체, NULL이 정렬에서 놓이는 위치의 화면 표시, 열 폭. 이런 줄에는 터미널에 ⓘ 표시가 붙습니다. STUDY 스키마의 사원·부서 행과 제약 조건 이름(SYS_C...)은 설명용 예시입니다.

11단계 RAC 기초: 공식 문서로 확인한 것은 crsctl check cluster -all의 노드별 CRS-4537·4529·4533 줄 형식(Clusterware 19c 문서 예시), olsnodes의 -n·-s·-c·-l·-t 옵션과 -n 출력 예시, crsctl stat res -t 표의 구조와 "Instance ... is running on node ..." 문구(21c Private Cloud Appliance 문서 예시), CRSCTL이 Grid 홈 bin에 있고 SRVCTL은 데이터베이스 홈에서 실행한다는 점, SRVCTL이 성공하면 아무것도 출력하지 않는다는 점, stop instance의 -stopoption 값, relocate service의 -oldinst·-newinst 문법, preferred·available 인스턴스의 뜻과 원래 인스턴스로 자동으로 돌아가지 않는다는 점, GV$ 뷰의 INST_ID, gc cr block 2-way·gc current block 2-way 대기 이벤트와 Cluster 대기 클래스(Real Application Clusters Administration and Deployment Guide 19c, Database Reference 19c)입니다. 확인하지 못한 것: srvctl status·config service와 config database 줄의 정확한 문구, "is not running" 문구, crsctl stat res -t의 열 간격과 서비스 자원 이름(ora.paydb.*.svc), check crs와 query crs activeversion의 화면 문구, olsnodes -s의 대소문자, 실패할 때의 PRC·PRK 오류 번호(지어내지 않고 ⓘ 안내로 바꿨습니다). 클러스터·노드·DB·서비스 이름, IP, 세션 수와 시각은 설명용 예시입니다. 레슨 104~108(RAC 19c CRSCTL·SRVCTL 실무 가이드 반영): 공식 문서로 확인한 것은 crsctl stat res -w 필터의 연산자(=, !=, co, st, en, AND, OR)와 ora. 자원을 CRSCTL로 직접 다루지 말라는 권고, 클러스터 명령이 OHASD에 기대어 동작한다는 점(Clusterware 19c), crsctl query css votedisk의 열 모양(19c OCR·보팅 파일 장 예시), CRS-4639 문구(19c 오류 메시지), query crs activeversion -f의 뜻(CRS-04172 사용법), srvctl config database의 줄 이름과 순서·-all 옵션, -startoption 기본값 OPEN, disable database가 인스턴스까지 비활성화한다는 점, 같은 대상에 SRVCTL을 동시에 실행하지 말라는 점, 종료 코드 0·1·2, -eval, -statefile·-scannumber 옵션의 뜻(RAC 19c), stop instance·relocate service의 -drain_timeout·-stopoption·-failover 사용 예(High Availability Overview 19c), srvctl config asm·status asm -verbose 모양(Clusterware 19c)입니다. 19c 문서 일부가 읽히지 않아 11.2 CRSCTL 문서로만 확인한 것: check crs의 CRS-4638 줄, config crs의 CRS-4622·CRS-4621, stop crs가 남은 자원이 있으면 실패하고 -f가 무조건 멈춘다는 설명, 여러 노드는 stop cluster가 자원 재배치를 막는다는 설명, "Located n voting disk(s)." 줄, -t 없는 NAME=·TYPE=·TARGET=·STATE= 모양. 확인하지 못한 것: crsctl stop crs·start crs의 진행 줄(CRS-2791, 2673, 2677, 2793, 4133, 4123, 2672, 2676, 6016, 6017, 6023, 6024), -init 표의 전체 목록과 상세 문구, Target·State 값(INTERMEDIATE, UNKNOWN 등)의 공식 정의, srvctl status -detail의 "Instance status:" 문구, config scan, scan_listener, vip, network, nodeapps, listener, service의 줄 문구, status diskgroup·vip 문구, stop home·start home 문법 전체와 상태 파일 안의 모양, -wait 옵션 설명, 권한이 없을 때의 오류 번호. 선생님이 주신 실무 가이드의 설명 가운데 "DB가 열린 채 crsctl stop crs를 하면 shutdown abort가 쓰일 수 있다", "stop diskgroup -force는 DB를 먼저 멈춰 주지 않는다"는 공식 문서에서 확인하지 못해 레슨에 그렇게 밝혀 두었습니다.

12단계 OS 원인 장애: 공식 자료로 확인한 것은 ORA-09925 문구와 조치(Oracle 오류 도움말), "Linux-x86_64 Error: 28: No space left on device" 줄 형식(My Oracle Support 문서 제목), 리눅스 오류 28이 ENOSPC라는 점(커널 소스), OOM killer의 badness와 oom_score_adj 범위(커널 문서), 커널 메시지 "invoked oom-killer", "Out of memory: Killed process"의 형식(현재 커널 소스 mm/oom_kill.c), HugePages가 스왑되지 않는다는 점과 THP 끄기·AMM과 함께 못 쓴다는 점(Linux 관리 문서 19c), CRS-2409·CRS-4700 문구, NTP가 있으면 CTSS가 observer 모드라는 점과 CTSS deprecated(Grid 설치 가이드 19c), Clusterware alert log 위치(Clusterware 19c 문제 해결 부록), chronyc tracking 항목과 makestep 경고, maxslewrate 기본값(chrony 4.5 문서)입니다. Oracle Linux 8 커널의 정확한 OOM 문구, OOM으로 죽었을 때 alert log에 남는 문구, systemctl status 화면 모양, crsctl check ctss 출력 전체, alert log의 [OCTSSD(...)] 표시는 확인하지 못했거나 실습용으로 만든 것입니다.

13단계 현장 업무 흐름: 데이터 파일 추가 문법과 DROP DATAFILE의 조건(DB가 열려 있어야 하고, 비어 있는 파일만, 첫 번째 파일은 안 됨, 실제 파일도 삭제됨)은 Administrator's Guide 19c로 확인했습니다. 접수 기록, 1차 보고, 작업계획서, 장애보고서 양식과 장애 등급 기준은 특정 표준을 옮긴 것이 아닌 실습용 예시입니다. 회사의 양식과 절차를 따르세요.

SQL 엔진은 실습에 필요한 SELECT(조인, 외부 조인, 하위 질의, WHERE, GROUP BY, HAVING, ORDER BY, 집계 함수), 실습용 STUDY 스키마의 INSERT·UPDATE·DELETE·COMMIT·ROLLBACK, 몇 가지 DDL만 흉내 냅니다. 숫자, 날짜, SID, PID, DBID, 백업 파일 이름과 업무 테이블의 행은 설명용 예시입니다.
